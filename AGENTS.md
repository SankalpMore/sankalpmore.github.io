# Dockio website working agreement

- Keep the GitHub website and the Sites copy synchronized for every website update, as requested by the owner. Follow the release procedure in README.md; reuse `.openai/hosting.json` and preserve Site access.
- GitHub is the canonical application source. Do not fork the marketing message between hosts. Record the originating GitHub commit in the Sites checkout with `scripts/prepare-sites-copy.mjs`.
- Serve enterprise sponsors, operations/workflow owners, AI/technology leaders, and delivery partners. Connect services to business outcomes and a clear next action.
- Treat newly supplied vision and user instructions as authoritative. Do not invent access to prior chats or Dot notes.
- Keep claims evidence-based. No fabricated clients, results, testimonials, official partnerships, certifications, or regulatory approval guarantees. Label representative workflows as examples.
- Keep sensitive strategy and personal planning out of the public repository and site.
- Preserve existing URLs, booking/email destinations, and brand unless the requested change needs them updated.
- Validate a production build, TypeScript, and representative desktop/mobile navigation before publication. Keep temporary QA scripts and screenshots outside the repository.
